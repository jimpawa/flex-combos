Flex Combos — prototype variants

Four prototypes of the Flex Combo homepage, testing two independent decisions against each other. Every build shares the same app, the same real pricing ladder and the same 3-leg flex model — only the two variables below change.

Variable 1 · rail layout

One rail — Popular and Flex combos share a single carousel, one card per fixture, alternating flexed and plain.

Two rails — Popular Combos and Flex Combos get separate carousels, split by whether a card can price a flex level above the 1.20 minimum.

Variable 2 · how the rule is worded

Loss framing — “2 picks can lose and you still win.”

Ratio framing — “1 of 3 must win”, anchoring the sentence on the same number as the control label (Flex 1/3).

Two of the six folders are duplicates

one-rail and one-rail-lose are the same build — same flags, same code, differing only in <title>. two-rails and two-rails-lose likewise. All six URLs are live so existing links keep working, but there are only four prototypes to review.

Every build is a self-contained ~2.6 MB page with React, Babel, all four Roboto faces and the 140-symbol pawaIconZ sprite inlined. Nothing is fetched from a CDN, so they work offline and in Maze. First paint takes a second while Babel compiles the JSX.
